## What each CQL level means

| Level | Implemented/proven scope | Limits |
|---|---|---|
| Advanced canonical CQL | MongoDB/SQLite/Neo4j: shared LINQ/manager planning, typed and metadata predicates, Boolean composition, membership, string operators, field comparisons, null/missing handling, ordering/paging, projections, scalar terminals, exact numeric domains, grouping/HAVING, same-provider inner/left joins, relationship predicates and selected-result composition within the checklist's declared shapes | Full EF/NHibernate parity, unrestricted POCO mapping, tooling and general transactional/graph semantics are incomplete. Native capability rejection is not feature support. |
| Bounded source CQL | Explicit native key equality/membership over configured records; three-record query/two-key subset; immutable mapped holon IDs/provenance; visitor-owned two-record Mongo snapshots; paired five/four physical rows; access isolation | Not arbitrary source scans, full text/search, arbitrary Name/Description/metadata filtering, general aggregation/joins, owned on-chain persistence or full ORM. Query capabilities define the exact contract. |
| Azure local subset | Parameterized native row predicates: canonical fields, string/Boolean metadata, Boolean composition, null/existence, membership, supported ordering/paging; projection and Count/LongCount/Any implementations present; emulator/native evidence retained | No hosted Azure acceptance; no equal-depth three-store parity certification. Earlier audit gates are historical, not a current comprehensive feature matrix. |
| Oracle bounded canonical subset | Bounded ID equality/membership; Name/Description equality or substring; string metadata equality, Boolean combinations and paging over authoritative catalogue; native local HTTP/Mongo pairing verified | No hosted Oracle; use orderBy None; sorting, full graph loading and full EF parity not enrolled. |
| Not CQL-certified here | Underlying provider implementation/SDK/storage evidence may exist, as recorded per row below | Do not call these fully CQL implemented or sandbox ready merely because SDK/CRUD exists. |

Public sources expose different native keys: IPFS CID, SOLID record ID, ActivityPub status ID, S3/GCS object key, chain account address, Cosmos validator address or Polkadot block hash. Public chain balances remain exact decimal strings and finalized RPC-reported state; this is not independent settlement proof. GCS public object queries are a different read representation from GoogleCloudOASIS's Firestore storage backend. S3 metadata reads are different from owned DynamoDB/S3 persistence.

- MongoDB/SQLite/Neo4j prove snapshot dirty detection/no-op saves, acknowledged save-state publication, optimistic revision-conditioned update/delete and per-save delta ownership within their scoped tests. This is not full session/identity-map/tooling parity.

- Live failover: Mongo to SQLite, SQLite to Mongo, Neo4j to Mongo; disabled failover returns provider-offline, enabled failover returns the same acknowledged identity/version/owner/content; independent visitor sees zero private records; all faults restored.
- One routing-v2 acknowledged create replicated exactly to all three stores. Existing broader replica baseline/repair/ACK-loss/disconnect proofs remain scoped to their retained fixtures.
- Auto is a scoring policy, not a promise to rotate. Score optimality, geographic performance, fairness, universal availability/100% uptime and every-provider failover/replication are not certified.
- Still incomplete: broader hosted/operator recovery, primary-write-authority migration, large-store certification, full rollback/history/child-parameter acceptance reconciliation and full ORM roadmap. Public query profiles do not grant canonical signed writes or source replication authority.
