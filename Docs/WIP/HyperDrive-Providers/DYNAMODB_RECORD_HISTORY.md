## Current implementation

`DynamoDBOASIS.RecordHistory.cs` adds a private, real AWSSDK.DynamoDBv2 write primitive for the three canonical tables. It reuses shared EmbeddedRecordHistory/StoredRecordVersions and existing strict stored-identity/projection decoding plus mutation reconciliation. It performs one authoritative strongly consistent GetItem, detached history staging, then exactly one conditional PutItem with ALL_OLD. Absent item requires attribute_not_exists(id); replacement compares the exact observed data_json, which includes the complete history envelope. No retry/merge, trimming, blind overwrite or fake transaction ID. Returned replacement attributes must match the observed original ID/data_json; create must return no old item. Unknown acknowledgments are fenced by existing DynamoDBMutationReconciliationException.

Client, table, attributes, canonical input and observed JSON are frozen before later awaits. A controlled read callback mutates the original table/payload to prove it cannot redirect the write. Table/type mismatches are rejected. Native attributes are detached; no caller ID/version/key publication occurs in this primitive. Public save owners must publish the returned staged version only AFTER native acknowledgment when integrated.

The primitive REQUIRES client MaxErrorRetry=0 before any I/O. Otherwise an SDK retry after an unknown first commit could return ConditionalCheckFailed and falsely look like known nonexecution. Current ordinary provider/client configuration has NOT been changed yet, and ordinary saves do NOT call the new method. A single-attempt condition failure remains explicit nonexecution evidence; other dispatched failures require reconciliation. This guard is not permission for HyperDrive to replay unknown writes.
