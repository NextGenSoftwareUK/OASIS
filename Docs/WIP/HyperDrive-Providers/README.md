# HyperDrive and provider working reports

Current execution strategy: **breadth before depth**. Non-storage maps/AI/indexers/identity services are classified explicitly and use the lighter canonical `NonStorageConformance.cs` (`capability-v1`): identity, honest non-storage capabilities, activation, one acknowledged read-only service probe, deactivation. Legacy map interfaces need explicit factory adaptation; reclassification alone is not a pass. Probe identity is validated before report publication so URL query credentials cannot be logged. [Provider matrix](PROVIDER_MATRIX.md) is the single per-provider status table; regenerate with `python Scripts/Providers/update_provider_matrix.py` (`--check` detects drift). One canonical `Providers/Shared/TestSupport/CoreStorageConformance.cs` exercises the core interface for every family through registered provider factories; existing family test hosts link this exact source rather than copying cases. Initial reusable host: `Scripts/Providers/Run-CoreStorageConformance.ps1` (model controls +native LocalFile; SQL family identity controls use the existing PostgreSQL host). This is the initial host binding, not a claim all229 provider factories are already configured. Register remaining family factories against the SAME suite and record blocked access explicitly. `CONFORMANCE_RESULTS.json` counts only hash-bound actual shared-suite reports, not older isolated unit totals.

Approximately one working day per family; record blockers and move on. Reuse existing EVM Nethereum and key-value bases; consolidate compatible SQL/document/IPFS/non-EVM policy without inventing empty base classes or forcing incompatible service protocols together. No more Polkadot/NEAR/SQLite depth in this phase. Global HyperDrive routing follows every applicable provider passing baseline; custom contracts, fee ledgers and crash recovery come afterward, priority providers first. Existing resources/cleanup ledger remains authoritative; no fresh runtimes or worktrees for this reorganization.


This folder contains this workstream's transient reports, audits, evidence inventories and handoffs. It is not the published product documentation and does not certify completion. Keep new reports here instead of adding them to `Docs/`, `Docs/Devs/` or the top level of `Docs/WIP/`.
