They reuse ONE existing execution scope, durable preparation server, independently verified original, one-shot submission and read-only finality loop; native and asset call authorization remain separate. Public native preparation/verifier ABI is preserved. Missing owner fails before wallet/signing/network. Pool acceptance is not completion. Failed dispatch, amount/action/asset/account mismatch, read failure and cancellation retain the original reconciliation identity; never replay.

Mint captures the typed amount, existing numeric asset ID and recipient before wallet I/O. Existing `TokenAddress`/`MintToWalletAddress` metadata aliases are accepted only without conflicts; metadata `Amount` must agree with the positive typed amount. Unsupported memo is rejected rather than dropped. Explicit other-provider requests fail; `Default` means the already-selected adapter. The returned wallet must belong to the minter avatar/provider; no first-key/service-key fallback. SDK verifies address/key agreement and the durable owner binds the expected canonical signer before ACK. Authenticated HTTP/manager layer still owns logged-avatar defaulting and privileged overrides; provider rejects an empty actor instead of guessing one.

Burn now uses typed `Amount` and the explicit owner account/key or mnemonic, not a hardcoded amount/empty target. The existing interface has no separate target account, so it burns the signer's own holding. Native Assets requires the signer to be asset admin as well; this is not arbitrary-holder ERC20 burn semantics. The same metadata precision, exact u128, role/minimum/dust preparation checks and final actual Burned amount apply.
